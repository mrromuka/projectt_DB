# Kaspi Магазин

Интернет-магазин на Flask и PostgreSQL: каталог с категориями и поиском, корзина, заказы, отзывы,
**кабинет продавца** и **админ-панель**.

## Роли

| Роль | Что может |
|------|-----------|
| Покупатель | каталог, поиск, корзина (+/−/удалить), оформление и отмена нового заказа, отзывы |
| Продавец | `/seller` — обзор продаж, добавление/редактирование/скрытие **своих** товаров, заказы на свои товары |
| Администратор | `/admin` — заказы и их статусы, товары, пользователи (роли, блокировка), категории, отзывы |

Вход — `/login`, выход — кнопка «Выйти» в шапке. Продавцом можно стать при регистрации
(`/register`, вариант «Продавец»), администратора создаёт команда `create-admin` (см. ниже).

Статусы заказа: **Новый → В обработке → Отправлен → Доставлен**, либо **Отменён**
(товары возвращаются на склад, из отменённого обратно вернуть нельзя). Статусы меняет администратор.

## Первый запуск (Windows)

```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

:: 1. обновить БД (добавляет роли, пароли, привязку продавцов; безопасно запускать повторно)
flask --app run init-db

:: 2. создать администратора
flask --app run create-admin

:: 3. запуск
python run.py
```

Сайт откроется на http://127.0.0.1:5000

Если база создаётся с нуля: сначала выполните `db/schema.sql`, затем `flask --app run init-db`.

> **Старые пользователи** (зарегистрированные до появления паролей) не могут войти, пока у них нет пароля.
> Задать его: `flask --app run set-password user@mail.com`.
> Старые продавцы из таблицы `sellers` без аккаунта остаются в каталоге, но войти в кабинет не смогут —
> создайте им аккаунт через регистрацию «Продавец».

## Рекомендации

Когда покупатель кладёт товар в корзину, сайт предлагает, что ещё ему может пригодиться.
Показывается в четырёх местах: сразу после «В корзину» (один раз), в корзине («С этим часто покупают»),
на странице товара («Похожие товары») и **после покупки** — в пустой корзине и в истории заказов
(«Вам может понравиться»). После покупки рекомендации строятся по последним 3 заказам; если заказов
ещё нет — показываем популярное.

Как подбираем — три правила по порядку, пока не наберётся 4 товара:

1. **Часто берут вместе** — смотрим прошлые заказы: что покупали в тех же заказах, где был этот товар
   (например, к телефону — чехол). Отменённые заказы не считаются.
2. **Из той же категории** — если заказов мало, добавляем товары той же категории: сначала с лучшим
   рейтингом по отзывам, потом самые продаваемые.
3. **Популярное** — если и этого не хватило, добавляем то, что в магазине покупают чаще всего.

Не рекомендуем то, что уже в корзине, скрытые товары и товары, которых нет в наличии.
Под каждым товаром написана причина («💡 Часто берут вместе»). Код и подробные комментарии — `app/recommendations.py`.
Новых таблиц и миграций не нужно: используются существующие заказы, отзывы и товары.

## Что ещё изменилось

* Пароли хранятся хэшами, все формы защищены CSRF-токеном, «Выйти» — POST-запрос.
* При оформлении заказа остаток на складе уменьшается (и проверяется, чтобы не продать больше, чем есть).
* Новые заказы получают статус `new` (раньше сразу ставился `delivered`).
* Скрытые товары (`products.is_active = false`) не показываются в каталоге; удалять товары нельзя,
  чтобы не ломать историю заказов — их скрывают.

## Настройки

По умолчанию используются локальные значения, но их можно переопределить переменными окружения:

| Переменная    | По умолчанию           |
|---------------|------------------------|
| `SECRET_KEY`  | `kaspi_super_secret_key` (**смените перед публикацией**) |
| `DB_HOST`     | `localhost`            |
| `DB_PORT`     | `5432`                 |
| `DB_NAME`     | `kaspi_market`         |
| `DB_USER`     | `postgres`             |
| `DB_PASSWORD` | `1234`                 |
